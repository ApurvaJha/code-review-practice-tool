      The Ideal Response Structure

      PM Follow-up & Discussion

      Actionable Answer Blueprints

      1. Product Ideation (The Technical Leverage Brainstorm)

      Step 1: Identify Unfair Technical Advantage - What data or infrastructure does the backend already process that users don't see?
      Step 2: Map to User Value - How does exposing this technical capability solve a pain point?
      Step 3: Define the V1 Scope - Explain how to launch it quickly using existing APIs.

      2. Product Discussion (The Problem-to-MVP Pipeline)

      Step 1: Uncover the "Why" - Don't accept the feature as requested. Define the actual user pain point.
      Step 2: Propose the MVP - Define the cheapest, fastest way to test if the solution works.
      Step 3: Define Success - State exactly what metric you will measure before building V2.

      3. Stakeholder Management (The Trade-Off Triangle)

      Step 1: Validate & Align - Start by enthusiastically agreeing with the business goal.
      Step 2: Expose the Hidden Risk - Translate technical debt into business impact.
      Step 3: Force a Choice - Present two clear options, giving the stakeholder the power to choose.

      4. Prioritization (The 70/20/10 Resource Rule)

      Step 1: Establish the Baseline - State your strict resource buckets: 70% Product, 20% KTLO, 10% Innovation.
      Step 2: Evaluate the Ask - Where does the new request fit, and what gets bumped?
      Step 3: Define Operational Cost - Always mention who supports the feature after it ships.
